# 2. Тест-план тестирования безопасности

**ID документа:** STP-FINSECURE-2026-001  
**Версия:** 1.0  
**Статус:** Готов к использованию  

## 2.1 Введение

Данный Тест-план конкретизирует Стратегию тестирования безопасности платформы FinSecure. Содержит конкретные активности, расписание, критерии входа/выхода и ссылки на тест-кейсы.

## 2.2 Объекты тестирования

1. Веб-приложение (https://app.finsecure.example)
2. iOS-приложение (версия X.Y)
3. Android-приложение (версия X.Y)
4. Backend API (api.finsecure.example)
5. Подсистема аутентификации и управления сессиями
6. Бизнес-логика платежей и переводов

## 2.3 Функции, подлежащие тестированию

### Аутентификация и управление сессиями
- Вход по паролю
- Многофакторная аутентификация (TOTP / push / SMS)
- Таймаут сессии и обработка параллельных сессий
- Процесс сброса пароля
- Механизмы блокировки учётной записи
- «Запомнить меня» / постоянные сессии

### Авторизация
- Горизонтальная эскалация привилегий (данные пользователя A → пользователя B)
- Вертикальная эскалация (клиент → администратор)
- IDOR на номера счетов, ID транзакций, документы
- Проверка матрицы ролей

### Валидация ввода и инъекции
- SQL Injection / NoSQL Injection
- Cross-Site Scripting (reflected, stored, DOM)
- Command Injection
- SSRF
- XML / XXE (при наличии)
- Template Injection

### Бизнес-логика
- Отрицательные суммы / овердрафт
- Race conditions при переводах
- Обход лимитов
- Повтор транзакций (replay)

### Криптография и транспорт
- Конфигурация TLS (протоколы, шифры, HSTS)
- Certificate pinning (мобильные)
- Чувствительные данные в транзите и на хранении
- Хранение ключей на мобильных устройствах

### Мобильные особенности
- Небезопасное хранение данных (Keychain / SharedPreferences / SQLite)
- Небезопасная коммуникация
- Сопротивление реверс-инжинирингу (базовый уровень)
- Deep linking / безопасность URL-схем
- Попытки обхода биометрической аутентификации
- Проблемы с бэкапами и debug-флагами

### API Security
- Broken Object Level Authorization
- Broken Authentication
- Excessive Data Exposure
- Rate limiting / потребление ресурсов
- Mass assignment
- Security misconfiguration

## 2.4 Функции, не подлежащие тестированию

- Внутренняя логика сторонних платёжных шлюзов
- Уязвимости ОС на устройствах пользователей
- Социальная инженерия конечных пользователей
- Физическая безопасность мобильных устройств

## 2.5 Подход

1. **Разведка и сбор информации** (1–2 дня)
2. **Автоматизированное сканирование** (SAST + DAST + SCA + мобильные сканеры)
3. **Ручное тестирование** по приоритетным attack surfaces
4. **Эксплуатация и Proof-of-Concept** для подтверждённых проблем
5. **Отчётность и ретестирование**

## 2.6 Критерии прохождения / непрохождения

Тест-кейс считается **непройденным**, если:
- Уязвимость подтверждена и воспроизводима, **или**
- Средство защиты отсутствует или неэффективно против тестируемого вектора атаки.

Серьёзность назначается с использованием CVSS 3.1 + бизнес-влияние.

## 2.7 Критерии приостановки

Тестирование приостанавливается, если:
- Критичное staging-окружение становится недоступным
- Деструктивное тестирование приводит к непреднамеренной потере данных
- Выдан legal / compliance hold

## 2.8 Результаты тестирования

1. Тест-план (данный документ)
2. Детальный отчёт по findings (с доказательствами)
3. Executive summary
4. Матрица рисков
5. Отчёт по ретестированию (после исправлений)

## 2.9 Требования к окружению

- Staging-окружение, идентичное production
- Тестовые учётные записи с разными ролями
- Jailbroken / rooted устройства + чистые устройства
- Прокси-инструменты (Burp Suite Professional / OWASP ZAP)
- Инструменты анализа мобильных приложений (MobSF, Frida, Objection и др.)

## 2.10 Ответственность

См. документ Стратегии (раздел 1.6).

## 2.11 Примерный график

| Этап                         | Длительность | Зависимости               |
|------------------------------|--------------|---------------------------|
| Kick-off и моделирование угроз | 2 дня      | Предоставлен доступ       |
| Автоматизированное сканирование | 3 дня     | Окружение готово          |
| Ручное тестирование веб + API | 7–10 дней  | Сканирование завершено    |
| Тестирование мобильных приложений | 5–7 дней | Приложения предоставлены |
| Отчётность                   | 3 дня        | Все тесты завершены       |
| Ретестирование               | 3–5 дней     | Исправления развёрнуты    |

## 2.12 Риски и меры по снижению

| Риск                              | Мера снижения                           |
|-----------------------------------|-----------------------------------------|
| Неполные данные в staging         | Генерация синтетических наборов данных  |
| WAF блокирует легитимные тесты    | Whitelist IP тестировщиков / отключение правил |
| Ограниченное время на мобильный реверс | Фокус на high-impact проблемах первыми |
| Scope creep                       | Строгий change control                  |
