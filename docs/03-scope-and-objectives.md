# 3. Область применения и цели (детально)

## 3.1 Бизнес-цели

Защита средств клиентов, персональных данных и доверия к бренду FinSecure путём обеспечения эффективности средств защиты от распространённых и продвинутых атак на веб- и мобильные банковские приложения.

## 3.2 Технические цели

- Убедиться, что аутентификацию нельзя обойти или злоупотребить ею.
- Подтвердить, что авторизация правильно реализует принцип наименьших привилегий.
- Обеспечить защиту чувствительных данных в транзите и на хранении.
- Проверить, что API не раскрывает избыточную информацию и не допускает mass assignment.
- Проверить мобильные приложения на небезопасное хранение, слабую криптографию и неправильную проверку сертификатов.
- Выявить ошибки бизнес-логики, которые могут привести к финансовым потерям.

## 3.3 Активы в области тестирования

| Актив                         | Критичность | Примечания                          |
|-------------------------------|-------------|-------------------------------------|
| Аутентификация клиентов       | Критическая | Пароли, MFA, биометрия              |
| Балансы и история счетов      | Критическая | Прямое финансовое влияние           |
| Функции переводов / платежей  | Критическая | Риск мошенничества                  |
| Персональные данные (ПДн)     | Высокая     | Требования законодательства         |
| Токены сессий / cookies       | Высокая     | Риск угона сессии                   |
| Интерфейсы админа / поддержки | Высокая     | Эскалация привилегий                |
| Локальное хранилище мобильных | Высокая     | Сценарии компрометации устройства   |

## 3.4 Краткое описание attack surface

- Публичные страницы входа и регистрации
- Аутентифицированный веб-дашборд
- Deep links и custom URL schemes мобильных приложений
- API endpoints (документированные и нет)
- WebSocket / real-time каналы (если есть)
- Функциональность загрузки файлов
- Процессы восстановления пароля и аккаунта
